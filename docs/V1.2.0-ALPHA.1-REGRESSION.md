# Sapiver Pattern Forge v1.2.0-alpha.1 regression record

Date: 2026-10-01

## Purpose

Introduce the internal backward-compatible layer model without changing the visible v1.1.5 editor workflow or repeat mathematics.

## Protected source

- `baseline/v1.1.5` is the frozen recovery branch.
- `main` remains the reviewed v1.1.5 application source.
- Development is isolated on `feature/layer-engine-v1.2`.
- No deployment was performed as part of this work.

## Layer migration

Legacy `pattern-forge-v1`, `pattern-forge-v2` and `pattern-forge-v3` projects are migrated on open to:

1. `layer-motifs` — imported images
2. `layer-drawing` — brush strokes and drawn shapes

New project saves use `pattern-forge-v4` and retain the existing `items[]` and `marks[]` collections with a `layerId` added to each artwork record.

## Regression checks completed

### Static checks

- Embedded JavaScript passes `node --check`.
- The feature-branch `index.html` Git blob is identical to the locally tested alpha file.

### Eight supplied v1.1.5 starter projects

All eight starter projects were opened in both the untouched v1.1.5 baseline and the v1.2.0-alpha.1 build.

For every starter project:

- no JavaScript/page errors were emitted;
- the editor canvas output matched the baseline;
- SVG export was byte-for-byte identical to the baseline;
- item and mark counts were preserved;
- the alpha saved as `pattern-forge-v4`;
- imported items migrated to `layer-motifs`;
- the active layer migrated to `layer-drawing`.

The matrix covers the existing straight, half-drop and brick starter designs.

### Drawing/mark migration fixture

A synthetic v3 project was tested with:

- an ink brush stroke crossing the tile edge;
- a line;
- an outlined rectangle;
- a filled ellipse;
- a freehand fill;
- a gradient fill.

Results:

- baseline and alpha editor canvas output matched;
- baseline and alpha SVG exports were byte-for-byte identical;
- all marks migrated to `layer-drawing`;
- save to v4 and reopen in the alpha produced identical canvas and SVG output.

## Known test limitation

The isolated browser harness injects the app into an opaque `about:blank` document. Chromium in the test environment blocks navigation to local and synthetic origins, so native IndexedDB persistence cannot be end-to-end tested in this harness. The alpha continues to call the full `projectData()` serializer for autosave, which now includes `layers` and `activeLayerId`; autosave is therefore code-reviewed but not yet browser-origin verified.

## Guardrails before layer UI

Before allowing users to reorder layers or create non-exporting guide layers:

- split editor rendering from export filtering so `export:false` layers may remain visible while editing;
- make SVG export iterate the actual layer order rather than relying on the current Motifs-then-Drawing order;
- add UI-specific tests for hide/show, opacity, lock, reorder, duplicate and delete.

These are deliberately deferred from alpha.1 so the first layer-engine commit remains a minimal backward-compatible change.
